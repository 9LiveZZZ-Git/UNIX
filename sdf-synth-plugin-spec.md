# SDF SYNTH 3D — JUCE Desktop Plugin Specification

> **Deliverables:** VST3 + Standalone (all platforms), AU (macOS)
> **GPU rendering:** OpenGL via JUCE's built-in `juce::OpenGLContext` (completely offline, zero external deps)
> **Reference implementation:** `sdf-synth-topo (3).jsx` (React/Three.js/WebAudio prototype, v3 with PBR textures + AO + Emissive)

## Claude Code Build Prompt

You are building a **desktop audio synthesizer plugin** (VST3/AU/Standalone) using JUCE 8. This plugin uses **3D Signed Distance Functions** as its core waveform engine. Instead of traditional oscillators, waveforms are generated by extracting horizontal cross-section contours through 3D SDF scenes — like MRI slices through geometry. The cross-section's radial profile at a given height becomes the waveform shape. Sweeping the slice height morphs the timbre continuously.

A working React/Three.js prototype exists at `sdf-synth-topo (3).jsx` — use it as the behavioral reference for every feature. This v3 prototype features a full **PBR material system** (6 texture channels: color, normal, roughness, displacement, AO, emissive), a **procedural texture library** (8 built-in materials), **displacement-to-audio modulation** (texture displacement distorts the waveform), and **emissive-to-audio amplitude modulation** (bright emissive regions boost the signal). This spec exhaustively documents the algorithms, architecture, and parameters so you can implement from scratch in C++/JUCE without needing to read the JS.

## 0. GPU Strategy: Why OpenGL, Not Dawn

Dawn (Google's WebGPU C++ implementation) was considered for the GPU rendering layer. Here's why **OpenGL via JUCE** is the right call:

| Criterion | OpenGL (JUCE built-in) | Dawn / WebGPU |
|-----------|------------------------|---------------|
| **JUCE integration** | `juce::OpenGLContext` + `juce::OpenGLRenderer` — native, zero-config | Custom integration required — manually attach Dawn surface to native window handle |
| **Shader language** | GLSL — the prototype's fragment shader translates **1:1** | WGSL — every shader must be rewritten |
| **External dependencies** | **None** — ships with JUCE | ~100 MB+ (Chromium infra, SPIRV-Tools, Tint compiler, abseil-cpp) |
| **Build complexity** | Zero extra CMake work | Dawn's CMake has 70+ internal targets; depot_tools recommended; vendoring is painful |
| **Offline / hermetic** | Fully self-contained — **no internet after initial JUCE fetch** | Dawn pulls submodules at configure time by default |
| **Platform support** | Windows (GL 4.1+), macOS (GL 4.1, deprecated but functional), Linux (GL 4.1+) | Windows (D3D12), macOS (Metal), Linux (Vulkan) |
| **Compute shaders** | GL 4.3+ (not on macOS 4.1 limit) | Full compute on all platforms |
| **Maturity in audio plugins** | Industry-proven (Vital, Surge XT, many JUCE plugins) | No known shipping audio plugin uses Dawn |
| **Rendering quality** | Identical — same raymarching algorithm | Identical — same algorithm, different API |

**Decision:** Use **OpenGL** via `juce::OpenGLContext`. The raymarcher GLSL from the prototype maps directly. Waveform generation stays on CPU (fast enough — the prototype does it in JavaScript). No internet needed, no external downloads, no build drama.

> **Dawn as future migration path:** If macOS fully removes OpenGL (unlikely near-term), Dawn/WebGPU becomes the fallback. The SDF evaluation code is cleanly separable, so porting GLSL→WGSL later is straightforward. But today, OpenGL is the pragmatic choice.

## 3. 3D SDF Primitives

All primitives operate in normalized space centered at origin. Return signed float: negative = inside, zero = surface, positive = outside.

```cpp
// SDFPrimitives3D.h — header-only
#pragma once
#include <cmath>
#include <algorithm>

namespace sdf {

inline float sphere(float x, float y, float z, float r) {
    return std::sqrt(x*x + y*y + z*z) - r;
}

inline float box(float x, float y, float z, float b) {
    float dx = std::abs(x) - b;
    float dy = std::abs(y) - b;
    float dz = std::abs(z) - b;
    float outside = std::sqrt(std::max(dx,0.f)*std::max(dx,0.f)
                            + std::max(dy,0.f)*std::max(dy,0.f)
                            + std::max(dz,0.f)*std::max(dz,0.f));
    float inside = std::min(std::max(dx, std::max(dy, dz)), 0.f);
    return outside + inside;
}

inline float torus(float x, float y, float z, float R, float r) {
    float q = std::sqrt(x*x + z*z) - R;
    return std::sqrt(q*q + y*y) - r;
}

inline float cylinder(float x, float y, float z, float r, float h) {
    float d = std::sqrt(x*x + z*z) - r;
    float dy = std::abs(y) - h;
    float outside = std::sqrt(std::max(d,0.f)*std::max(d,0.f)
                            + std::max(dy,0.f)*std::max(dy,0.f));
    float inside = std::min(std::max(d, dy), 0.f);
    return outside + inside;
}

inline float octahedron(float x, float y, float z, float s) {
    return (std::abs(x) + std::abs(y) + std::abs(z) - s) * 0.57735f;
}

} // namespace sdf
```

### Shape Evaluation with Size Scaling

The prototype scales each shape differently for visual/sonic balance. Replicate exactly:

```cpp
float evalShape(ShapeType shape, float x, float y, float z, float size) {
    switch (shape) {
        case Sphere:     return sdf::sphere(x, y, z, size);
        case Box:        return sdf::box(x, y, z, size * 0.75f);
        case Torus:      return sdf::torus(x, y, z, size * 0.65f, size * 0.25f);
        case Cylinder:   return sdf::cylinder(x, y, z, size * 0.5f, size * 0.8f);
        case Octahedron: return sdf::octahedron(x, y, z, size);
        default:         return sdf::sphere(x, y, z, size);
    }
}
```

## 4. SDF Operations & Domain Transforms

### Boolean Operations

```cpp
namespace sdf::ops {

inline float smoothMin(float a, float b, float k) {
    if (k < 0.001f) return std::min(a, b);
    float h = std::max(k - std::abs(a - b), 0.f) / k;
    return std::min(a, b) - h * h * h * k / 6.f;
}

// 4 operations matching the prototype:
// "smooth union" → smoothMin(d1, d2, k)
// "union"        → min(d1, d2)
// "intersection" → max(d1, d2)
// "subtraction"  → max(d1, -d2)

} // namespace sdf::ops
```

### Domain Twist

Applied to coordinates BEFORE shape evaluation. Rotates XZ plane as a function of Y:

```cpp
// twist parameter range: [0, 6]
if (twist > 0.01f) {
    float c = std::cos(twist * y);
    float s = std::sin(twist * y);
    float nx = x * c - z * s;
    float nz = x * s + z * c;
    x = nx; z = nz;
}
```

### Full Scene Evaluation

```cpp
float SDFScene3D::evaluate(float x, float y, float z) const {
    float sx = x, sy = y, sz = z;

    // Domain twist
    if (twist > 0.01f) {
        float c = std::cos(twist * sy), s = std::sin(twist * sy);
        float nx = sx*c - sz*s, nz = sx*s + sz*c;
        sx = nx; sz = nz;
    }

    // Shape A (may be custom voxel SDF or built-in)
    float d1 = (shape1 == Custom && voxelSDF)
        ? voxelSDF->sample(sx, sy, sz)
        : evalShape(shape1, sx, sy, sz, size1);

    // Shape B offset by (offsetX, offsetY, 0)
    float d2 = (shape2 == Custom && voxelSDF)
        ? voxelSDF->sample(sx - offsetX, sy - offsetY, sz)
        : evalShape(shape2, sx - offsetX, sy - offsetY, sz, size2);

    // Combine
    switch (operation) {
        case SmoothUnion:   return sdf::ops::smoothMin(d1, d2, smoothK);
        case Union:         return std::min(d1, d2);
        case Intersection:  return std::max(d1, d2);
        case Subtraction:   return std::max(d1, -d2);
    }
}
```

## 5. Custom Mesh Import — OBJ to Voxel SDF

Users drag-and-drop `.obj` files onto the plugin. The pipeline:

**OBJ → Parse → Normalize → Voxelize → Trilinear-sampled SDF**

### 5.1 OBJ Parser

```
Parse lines:
  "v x y z"     → vertices array
  "f a b c ..."  → triangulate fan: for i in [1, n-2]: face(idx[0], idx[i], idx[i+1])
                   Handle "f a/b/c" format (split on '/', take first int, subtract 1)

Normalize mesh:
  Compute bounding box [min, max] across all 3 axes
  Center = (min + max) / 2
  Extent = max component of (max - min)
  Scale factor = 1.4 / extent   (leaves margin in [-1,1]³)
  For each vertex: v = (v - center) * scale
```

### 5.2 Point-to-Triangle Distance

Used by voxelizer. Returns squared distance from point `p` to triangle `abc`. Must handle all 7 Voronoi regions (3 vertices, 3 edges, 1 face interior):

```cpp
float ptTriDistSq(Vec3 p, Vec3 a, Vec3 b, Vec3 c) {
    Vec3 ab = b - a, ac = c - a, ap = p - a;
    float d1 = dot(ab, ap), d2 = dot(ac, ap);
    if (d1 <= 0 && d2 <= 0) return dot(ap, ap);         // Region: vertex A

    Vec3 bp = p - b;
    float d3 = dot(ab, bp), d4 = dot(ac, bp);
    if (d3 >= 0 && d4 <= d3) return dot(bp, bp);         // Region: vertex B

    Vec3 cp = p - c;
    float d5 = dot(ab, cp), d6 = dot(ac, cp);
    if (d6 >= 0 && d5 <= d6) return dot(cp, cp);         // Region: vertex C

    float vc = d1*d4 - d3*d2;
    if (vc <= 0 && d1 >= 0 && d3 <= 0) {                 // Region: edge AB
        float v = d1 / (d1 - d3);
        Vec3 cl = a + ab * v;
        Vec3 df = p - cl;
        return dot(df, df);
    }

    float vb = d5*d2 - d1*d6;
    if (vb <= 0 && d2 >= 0 && d6 <= 0) {                 // Region: edge AC
        float w = d2 / (d2 - d6);
        Vec3 cl = a + ac * w;
        Vec3 df = p - cl;
        return dot(df, df);
    }

    float va = d3*d6 - d5*d4;
    if (va <= 0 && (d4-d3) >= 0 && (d5-d6) >= 0) {       // Region: edge BC
        float w = (d4 - d3) / ((d4 - d3) + (d5 - d6));
        Vec3 cl = b + (c - b) * w;
        Vec3 df = p - cl;
        return dot(df, df);
    }

    // Region: face interior
    float denom = 1.f / (va + vb + vc);
    float v2 = vb * denom, w2 = vc * denom;
    Vec3 cl = a + ab * v2 + ac * w2;
    Vec3 df = p - cl;
    return dot(df, df);
}
```

### 5.3 Voxelization

Resolution: **24³** (13,824 voxels). Higher → slower but more detail; lower → audio aliasing.

```
For each voxel (ix, iy, iz) in [0, res)³:
    p = map voxel center to [-1, 1]³:
        px = (ix / (res-1)) * 2 - 1
        py = (iy / (res-1)) * 2 - 1
        pz = (iz / (res-1)) * 2 - 1

    Find nearest triangle:
        For each triangle face:
            dist² = ptTriDistSq(p, v[f[0]], v[f[1]], v[f[2]])
            If dist² < minDist²:
                minDist² = dist²
                closestNormal = triangle face normal
                closestDiff = p - triangle centroid

    Determine sign (inside/outside):
        sign = dot(closestDiff, closestNormal) > 0 ? +1 : -1

    grid[iz * res² + iy * res + ix] = sqrt(minDist²) * sign
```

**Triangle face normal**: `normalize(cross(b - a, c - a))`
**Triangle centroid**: `(a + b + c) / 3`

### 5.4 Trilinear Sampling

Runtime SDF evaluation from voxel grid:

```cpp
float VoxelSDF::sample(float x, float y, float z) const {
    // Map [-1, 1] → [0, res-1]
    float u = (x + 1.f) * 0.5f * (res - 1);
    float v = (y + 1.f) * 0.5f * (res - 1);
    float w = (z + 1.f) * 0.5f * (res - 1);

    // Clamp / return large distance for out-of-bounds
    if (u < 0 || v < 0 || w < 0 || u >= res-1 || v >= res-1 || w >= res-1)
        return 1.5f;

    int ix = (int)u, iy = (int)v, iz = (int)w;
    float fx = u - ix, fy = v - iy, fz = w - iz;

    // Trilinear interpolation of 8 corners
    auto at = [&](int zi, int yi, int xi) {
        return grid[zi * res * res + yi * res + xi];
    };
    float c00 = at(iz,iy,ix)*(1-fx) + at(iz,iy,ix+1)*fx;
    float c10 = at(iz,iy+1,ix)*(1-fx) + at(iz,iy+1,ix+1)*fx;
    float c01 = at(iz+1,iy,ix)*(1-fx) + at(iz+1,iy,ix+1)*fx;
    float c11 = at(iz+1,iy+1,ix)*(1-fx) + at(iz+1,iy+1,ix+1)*fx;
    float c0 = c00*(1-fy) + c10*fy;
    float c1 = c01*(1-fy) + c11*fy;
    return c0*(1-fz) + c1*fz;
}
```

**Threading**: Voxelization runs on a background thread. Use atomic pointer swap to deliver finished `VoxelSDF` to the audio thread. Show "VOXELIZING..." in GUI during computation.

## 6. MRI Cross-Section Extraction

This is the **core innovation**. At a given Y height (`scanHeight`), extract the horizontal cross-section contour of the 3D SDF scene by marching outward from center along radial rays.

### Algorithm

```
extractContour(evalFn, scanHeight, numSamples = 512):
    contour = []

    For i in [0, numSamples):
        theta = (i / numSamples) * 2π
        dir = (cos(theta), 0, sin(theta))    // radial direction in XZ plane

        // March outward to find ALL sign changes (handles multiple shells)
        steps = 64
        maxR = 2.0
        crossings = []
        prevD = evalFn(0, scanHeight, 0)      // SDF at center

        For s in [1, steps]:
            r = (s / steps) * maxR
            d = evalFn(dir.x * r, scanHeight, dir.z * r)

            If sign change between prevD and d:
                // Binary search refinement (16 iterations)
                rLo = (s-1)/steps * maxR
                rHi = r
                For 16 iterations:
                    rMid = (rLo + rHi) / 2
                    dMid = evalFn(dir.x * rMid, scanHeight, dir.z * rMid)
                    If same sign as prevD: rLo = rMid
                    Else: rHi = rMid
                crossings.append((rLo + rHi) / 2)

            prevD = d

        // Use outermost crossing (visible surface)
        If crossings not empty:
            r = crossings.last()
            contour.append({theta, r, valid=true, x=cos(theta)*r, z=sin(theta)*r})
        Else:
            contour.append({theta, r=0, valid=false})

    Return contour
```

### Scan Point Interpolation

For any angle θ, interpolate the contour with the MRI morph parameter:

```
getScanPoint(theta, contour, scanRadius, topoMorph):
    // Find surrounding contour samples
    ci = (theta / 2π) * contour.length
    i0 = floor(ci) % n
    i1 = (i0 + 1) % n
    frac = ci - floor(ci)

    // Interpolate contour radius
    cr = contour[i0].r * (1 - frac) + contour[i1].r * frac

    // Blend between circular path and contour path
    r = scanRadius * (1 - topoMorph) + cr * topoMorph

    Return (cos(theta) * r, sin(theta) * r, r)
```

`topoMorph = 0`: perfect circle at `scanRadius` (traditional wavetable scan)
`topoMorph = 1`: scan path IS the cross-section contour (MRI mode)

## 7. Waveform Generation

Two modes based on `topoMorph` value, with optional **displacement texture modulation** and **emissive amplitude modulation**.

### Texture-to-Audio Pipelines (v3)

Two texture channels feed into the audio waveform:

1. **Displacement → additive distortion**: Displacement texture data adds harmonic complexity to the waveform. Bipolar modulation shifts the waveform shape.
2. **Emissive → amplitude modulation**: Bright emissive regions boost the signal amplitude. This creates a direct link between visual glow and audio loudness.

### CPU-Side Triplanar Texture Sampling

Both displacement and emissive use the same CPU-side triplanar sampling:

```
sampleTexCPU(texData, x, y, z, scale):
    // Triplanar blend weights from position (approximate normal)
    len = sqrt(x*x + y*y + z*z) + 0.001
    nx = abs(x/len), ny = abs(y/len), nz = abs(z/len)
    wsum = nx + ny + nz + 0.001

    // Sample texture at triplanar UVs (scaled, wrapped)
    sample(u, v) = texData.pixel_at(wrap(u*scale*0.5+0.5), wrap(v*scale*0.5+0.5)).r / 255

    Return (sample(y,z)*nx + sample(x,z)*ny + sample(x,y)*nz) / wsum
```

### Waveform Generation with Texture Modulation

```
generateWaveform(evalFn, contour, params, dispData, dispAmt, emData, emInt, numSamples):
    // ... compute base sample as before (MRI or Circular mode) ...

    For i in [0, numSamples):
        theta = (i / n) * 2π
        pt = getScanPoint(theta, ...)

        // Displacement: additive bipolar distortion
        If dispData exists AND dispAmt > 0:
            dv = sampleTexCPU(dispData, pt.x, scanHeight, pt.z, texScale)
            samples[i] += (dv - 0.5) * dispAmt * 4.0   // subtle harmonic distortion

        // Emissive: multiplicative amplitude boost
        If emData exists AND emInt > 0:
            ev = sampleTexCPU(emData, pt.x, scanHeight, pt.z, texScale)
            samples[i] *= 1 + ev * emInt * 0.8          // boost up to ~1.8x at full

        samples[i] = clamp(samples[i], -1, 1)

    Return samples
```

The emissive amplitude modulation is especially effective with **Lava** (hot cracks boost harmonics) and **Circuit Board** (LED nodes create rhythmic amplitude patterns).

### MRI Mode (topoMorph > 0.5)

The waveform IS the radial profile of the cross-section — the geometric shape of the slice becomes the shape of the wave.

```
generateWaveform_MRI(evalFn, contour, params, numSamples):
    // Collect all contour radii at each sample angle
    radii = []
    For i in [0, numSamples):
        theta = (i / n) * 2π
        Interpolate contour radius at theta → radii[i]

    meanR = average(radii)
    maxDev = max(|r - meanR| for r in radii)   // at least 0.01

    // Blend factor for adding SDF detail
    sdfMix = max(0, (1 - topoMorph) * 2)

    For i in [0, numSamples):
        profileVal = (radii[i] - meanR) / maxDev    // normalized [-1, 1]
        theta = (i / n) * 2π
        pt = getScanPoint(theta, contour, scanRadius, topoMorph)
        sdfVal = evalFn(pt.x, scanHeight, pt.z) * distScale
        samples[i] = clamp(profileVal * (1 - sdfMix*0.5) + sdfVal * sdfMix*0.5, -1, 1)

    // Apply displacement modulation (see above)

    Return samples
```

### Circular Mode (topoMorph ≤ 0.5)

Traditional: sample SDF along circular/morphed path.

```
generateWaveform_Circular(evalFn, contour, params, numSamples):
    For i in [0, numSamples):
        theta = (i / n) * 2π
        pt = getScanPoint(theta, contour, scanRadius, topoMorph)
        d = evalFn(pt.x, scanHeight, pt.z)
        samples[i] = clamp(d * distScale, -1, 1)

    // Apply displacement modulation (see above)

    Return samples
```

### Wavetable Size

- **Audio wavetable**: 2048 samples (good balance of quality vs rebuild cost)
- **Visual waveform**: match canvas/viewport width in pixels
- **Contour resolution**: 512 angular samples

## 8. Audio Engine — Wavetable Oscillator

### Phase Accumulator with Cubic Interpolation

```cpp
class SDFOscillator {
    float phase = 0.f;        // [0, 1)
    float phaseInc = 0.f;     // freq / sampleRate
    const float* wavetable;   // pointer to current wavetable (2048 samples)
    int tableSize = 2048;

    void setFrequency(float hz, float sampleRate) {
        phaseInc = hz / sampleRate;
    }

    float nextSample() {
        float pos = phase * tableSize;
        int i0 = (int)pos % tableSize;
        int im1 = (i0 - 1 + tableSize) % tableSize;
        int i1 = (i0 + 1) % tableSize;
        int i2 = (i0 + 2) % tableSize;
        float f = pos - std::floor(pos);

        // Cubic Hermite interpolation
        float a = wavetable[im1], b = wavetable[i0];
        float c = wavetable[i1], d = wavetable[i2];
        float cb = c - b, ab = a - b, db = d - b;
        float sample = b + 0.5f * f * (cb + f * (cb - ab + f * (3.f*(ab-cb) + db)));

        phase += phaseInc;
        phase -= std::floor(phase);  // wrap [0, 1)

        return sample;
    }
};
```

### Wavetable Update Strategy

- Rebuild ONLY when parameters change (dirty flag system)
- Rebuild cost: ~100μs for 2048 samples (fine for message thread)
- Double-buffer: compute new table, then atomic swap pointer
- Optional crossfade: 64-sample blend between old and new table to prevent clicks

## 9. Polyphonic Voice Architecture

### SDFVoice (juce::SynthesiserVoice)

```
Each voice has:
  - SDFOscillator (reads shared wavetable — all voices share the same timbre)
  - juce::ADSR envelope
  - Per-voice state: currentNote, velocity, isActive
  - Optional: per-voice filter (juce::dsp::StateVariableTPTFilter)

noteOn:
  - Set oscillator frequency from MIDI note
  - Start ADSR
  - Scale velocity → amplitude

noteOff:
  - Trigger ADSR release

renderNextBlock:
  For each sample in buffer:
    raw = oscillator.nextSample()
    env = adsr.getNextSample()
    output = raw * env * velocity
    Add to output buffer (voices are summed)
```

### Voice Count

16 voices. All share the same wavetable (same SDF scene), but each runs its own phase accumulator and ADSR. This means timbre is monophonic (one SDF scene) but pitch is polyphonic.

### SDFSynthesiser

Standard `juce::Synthesiser` subclass. Add 16 `SDFVoice` instances and one `juce::SynthesiserSound` that accepts all MIDI channels.

These parameters trigger a contour re-extraction + wavetable rebuild:

**Scene evaluation** — identical SDF primitives and operations as CPU code, duplicated in GLSL. Keep them in sync.

**Displacement-modified SDF (v2)** — when a displacement map is active, the SDF surface is deformed:

```glsl
float sceneDisp(vec3 p) {
    float d = scene(p);

        vec3 n = calcNormal(p);  // approximate surface normal
        float disp = triplanarDisp(p, n);
        d -= disp * uDispAmt;

    return d;
}
```

**MRI clipping** — the shape is clipped by a horizontal plane at `uScanY`. Everything below the plane is invisible, revealing the interior cross-section:

```glsl
float sceneClipped(vec3 p) {
    float shape = sceneDisp(p);  // uses displacement-modified SDF
    float clipPlane = uScanY - p.y;   // positive below scan plane
    return max(shape, clipPlane);
}
```

**Cross-section interior rendering** — where the clip plane intersects the shape interior, render with distance-band rings. Uses solid opaque shading (v2: darker, moodier aesthetic):

bool isSliceFace = abs(p.y - uScanY) < 0.003 && scene(p) < 0.0;
if (isSliceFace) {

**PBR Triplanar Texture Mapping (v2)** — four independent texture channels, each sampled triplanarly:

```glsl
// Generic triplanar sampler — used for all 4 map channels
vec3 triplanarTex(sampler2D tex, vec3 p, vec3 n) {
    vec3 w = abs(n);
    w = w / (w.x + w.y + w.z + 0.001);
    vec2 sc = vec2(uTexScale);
    vec3 tx = texture2D(tex, p.yz * sc * 0.5 + 0.5).rgb;
    vec3 ty = texture2D(tex, p.xz * sc * 0.5 + 0.5).rgb;
    vec3 tz = texture2D(tex, p.xy * sc * 0.5 + 0.5).rgb;
    return tx * w.x + ty * w.y + tz * w.z;
}

// Displacement triplanar (returns float, single channel)
float triplanarDisp(vec3 p, vec3 n) {
    vec3 w = abs(n);
    w = w / (w.x + w.y + w.z + 0.001);
    vec2 sc = vec2(uTexScale);
    float dx = texture2D(uTexDisp, p.yz * sc * 0.5 + 0.5).r;
    float dy = texture2D(uTexDisp, p.xz * sc * 0.5 + 0.5).r;
    float dz = texture2D(uTexDisp, p.xy * sc * 0.5 + 0.5).r;
    return dx * w.x + dy * w.y + dz * w.z;
}

// Normal map perturbation
vec3 triplanarNorm(vec3 p, vec3 n) {
    vec3 w = abs(n);
    w = w / (w.x + w.y + w.z + 0.001);
    vec2 sc = vec2(uTexScale);
    vec3 nx = texture2D(uTexNorm, p.yz * sc * 0.5 + 0.5).rgb * 2.0 - 1.0;
    vec3 ny = texture2D(uTexNorm, p.xz * sc * 0.5 + 0.5).rgb * 2.0 - 1.0;
    vec3 nz = texture2D(uTexNorm, p.xy * sc * 0.5 + 0.5).rgb * 2.0 - 1.0;
    vec3 perturb = nx * w.x + ny * w.y + nz * w.z;
    return normalize(n + perturb * uNormInt);
}
```

**Roughness-Based Specular (v2)** — specular power and intensity vary with roughness map:

```glsl
float roughness = 0.5;  // default
if (uHasTexRough > 0.5) {
    roughness = triplanarTex(uTexRough, p, n).r + uRoughOff;
    roughness = clamp(roughness, 0.0, 1.0);
}
float specPow = mix(120.0, 4.0, roughness);    // smooth → sharp
float specInt = mix(0.7, 0.03, roughness);      // smooth → bright
```

**Three-Light Shading Model (v2)** — key + fill + rim lights:

```glsl
vec3 ld1 = normalize(vec3(2.0, 3.0, 1.5));    // key light
vec3 ld2 = normalize(vec3(-1.5, 0.5, -1.0));  // fill light
vec3 ld3 = normalize(vec3(0.0, -1.0, 2.0));   // rim light

float diff = max(dot(n, ld1), 0.0) * 0.7
           + max(dot(n, ld2), 0.0) * 0.25
           + max(dot(n, ld3), 0.0) * 0.15;

// Specular (Blinn-Phong with roughness)
vec3 h1 = normalize(ld1 + viewDir);
float spec = pow(max(dot(n, h1), 0.0), specPow) * specInt;
```

**Ambient Occlusion (v3)** — darkens crevices by multiplying the ambient lighting term. Cheap and effective:

```glsl
float ambient = 0.4;
if (uHasTexAO == 1) {
    float ao = triplanarTex(uTexAO, p * uTexScale, n).r;
    ao = mix(1.0, ao, uAOInt);  // 0 intensity = no effect, 1.0 = full AO
    ambient *= ao;               // darken crevices
}
```

**Emissive/Glow (v3)** — self-illuminating regions, additive on top of all lighting. Independent of light direction:

```glsl
// After all lighting calculation:
if (uHasTexEmit == 1) {
    vec3 emitCol = triplanarTex(uTexEmit, p * uTexScale, n) * uEmitInt;
    col += emitCol;  // additive — bright regions glow regardless of lighting
}
```

The emissive channel is especially impactful with **Lava** (orange-red crack glow) and **Circuit Board** (green LED node glow).

**Base color: solid opaque** — teal-green base rather than transparent:

```glsl
vec3 bc = vec3(0.08, 0.55, 0.6);  // opaque teal-green
// Subtle fresnel rim
float fres = pow(1.0 - max(dot(n, viewDir), 0.0), 4.0);
bc += vec3(0.0, 0.15, 0.15) * fres * 0.4;

// Blend with color texture if present
if (uHasTex > 0.5) {
    vec3 texCol = triplanarTex(uTex, p * uTexScale, n) * uTexBright;
    bc = mix(bc, texCol, uTexBlend);
}

// Final shading: ambient (with AO) + diffuse + specular
col = bc * (ambient + diff * 0.5 * shadow + diff2 * 0.15 + diff3 * 0.1)
    + vec3(0.5, 0.9, 1.0) * spec * shadow * 0.5;

// Emissive: additive on top
if (uHasTexEmit == 1) {
    col += triplanarTex(uTexEmit, p * uTexScale, n) * uEmitInt;
}
```

**HDR Skybox Background** — when a ray misses the SDF scene, sample the environment map instead of a flat color. Uses equirectangular projection for simplicity (single 2D texture):

```glsl
// Convert ray direction to equirectangular UV
vec2 equirectUV(vec3 rd) {
    float phi = atan(rd.z, rd.x);                        // azimuth [-π, π]
    float theta = asin(clamp(rd.y, -1.0, 1.0));          // elevation [-π/2, π/2]
    return vec2(phi / (2.0 * 3.14159) + 0.5,             // u: [0, 1]
                theta / 3.14159 + 0.5);                   // v: [0, 1]
}

// Background: skybox or fallback
vec3 bg;
if (uHasSkybox == 1) {
    vec3 rotRd = rd;
    // Apply skybox rotation (azimuthal)
    float cr = cos(uSkyboxRot), sr = sin(uSkyboxRot);
    rotRd.xz = mat2(cr, -sr, sr, cr) * rotRd.xz;
    vec3 hdr = texture2D(uSkybox, equirectUV(rotRd)).rgb;
    // Tone mapping: Reinhard with exposure
    bg = hdr * uSkyboxExp;
    bg = bg / (bg + vec3(1.0));  // Reinhard tone map
} else {
    bg = vec3(0.015, 0.025, 0.03);  // fallback: near-black
}
float vignette = 1.0 - 0.12 * dot(uv, uv);  // subtle vignette
```

**Environment Reflections** — PBR surfaces reflect the skybox based on roughness and reflection intensity:

```glsl
// After computing surface color (col):
if (uHasSkybox == 1 && uSkyboxRefl > 0.001) {
    vec3 reflDir = reflect(rd, n);
    // Apply skybox rotation
    float cr = cos(uSkyboxRot), sr = sin(uSkyboxRot);
    reflDir.xz = mat2(cr, -sr, sr, cr) * reflDir.xz;

    // Blur: offset UVs by roughness to fake convolution
    // (true IBL would use prefiltered mip levels — this is the cheap approximation)
    vec2 reflUV = equirectUV(reflDir);
    vec3 envCol = texture2D(uSkybox, reflUV).rgb * uSkyboxExp;
    envCol = envCol / (envCol + vec3(1.0));  // tone map

    // Fresnel-weighted reflection: more reflection at grazing angles
    float fresRefl = pow(1.0 - max(dot(n, -rd), 0.0), 5.0);
    float reflAmount = mix(0.04, 1.0, fresRefl) * uSkyboxRefl;

    // Roughness reduces reflection clarity (lerp toward diffuse ambient)
    reflAmount *= (1.0 - roughness * uSkyboxBlur);

    col = mix(col, envCol, reflAmount);
}
```

**Image-Based Ambient Lighting** — the skybox subtly tints the ambient term for more natural shading:

```glsl
// Sample skybox in the normal direction for ambient tint
if (uHasSkybox == 1) {
    vec3 ambDir = n;
    float cr = cos(uSkyboxRot), sr = sin(uSkyboxRot);
    ambDir.xz = mat2(cr, -sr, sr, cr) * ambDir.xz;
    vec3 envAmbient = texture2D(uSkybox, equirectUV(ambDir)).rgb * uSkyboxExp * 0.15;
    envAmbient = envAmbient / (envAmbient + vec3(1.0));
    col += bc * envAmbient;  // tint base color with environment
}
```

## 14. PBR Material System & Texture Pipeline

The v3 prototype implements a full **Physically Based Rendering** material system with 6 independent texture channels. Four affect only GPU rendering, while displacement and emissive also modulate the audio waveform.

### 14.1 Texture Channels

| Channel | GPU Effect | Audio Effect | Default (no texture) |
|---------|-----------|--------------|---------------------|
| **Color** (diffuse) | Surface albedo via triplanar mapping | None | Solid teal `vec3(0.08, 0.55, 0.6)` |
| **Normal** | Surface detail via normal perturbation | None | Flat normals (from SDF gradient) |
| **Roughness** | Specular power/intensity variation | None | 0.35 uniform roughness |
| **Displacement** | SDF surface deformation (`d -= disp * dispAmt`) | Additive waveform distortion (`(dv-0.5)*dispAmt*4`) | No displacement |
| **AO** (Ambient Occlusion) | Darkens crevices (`ambient *= ao`) | None (GPU only) | 1.0 uniform (no darkening) |
| **Emissive** (Glow) | Additive self-illumination (`col += emit * emitInt`) | Amplitude modulation (`s *= 1 + ev*emInt*0.8`) | No emission (black) |

### 14.2 Texture Loading

Accept PNG, JPG. Load via `juce::ImageFileFormat`, upload to OpenGL texture with `GL_REPEAT` wrap mode. Each channel has its own `sampler2D` uniform and `uHasTexXxx` flag.

```cpp
// TextureSystem manages 6 GL texture slots
struct TextureSlot {
    GLuint textureId = 0;
    bool loaded = false;
    juce::Image sourceImage;         // retained for CPU sampling (disp + emit)
    std::vector<uint8_t> pixelData;  // RGBA for CPU audio sampling
    int width = 0, height = 0;
};

TextureSlot colorTex, normalTex, roughTex, dispTex, aoTex, emitTex;
```

Note: Both `dispTex` and `emitTex` retain CPU-side pixel data for audio modulation. The other 4 channels are GPU-only.

### 14.3 For Custom OBJ Meshes

Generate spherical UVs during import:

```cpp
for each vertex (vx, vy, vz):
    float r = sqrt(vx*vx + vy*vy + vz*vz);
    if (r < 0.001f) r = 0.001f;
    float u = 0.5f + atan2(vz, vx) / (2π);
    float v = 0.5f + asin(clamp(vy / r, -1, 1)) / π;
```

Custom mesh overlay uses `MeshStandardMaterial` equivalent (PBR) rather than basic Phong. Apply all 6 texture maps to the mesh material (color → map, normal → normalMap, roughness → roughnessMap, displacement → displacementMap, AO → aoMap, emissive → emissiveMap).

### 14.4 For Raymarched Built-in Shapes

All 6 channels use triplanar mapping in the GLSL shader (see Section 11). The `uTexScale` parameter controls UV scaling for all channels simultaneously.

### 14.5 CPU-Side Texture Sampling (Displacement + Emissive)

For the texture-to-audio pipelines, displacement AND emissive map pixel data are retained on CPU. Both use the same triplanar sampling with bilinear interpolation from the RGBA pixel array:

```cpp
// TextureSampler.h
float sampleBilinear(const uint8_t* data, int w, int h, float u, float v) {
    // Wrap UV to [0, 1]
    u = u - std::floor(u);
    v = v - std::floor(v);
    float fx = u * (w - 1), fy = v * (h - 1);
    int ix = (int)fx, iy = (int)fy;
    float dx = fx - ix, dy = fy - iy;
    int ix1 = (ix + 1) % w, iy1 = (iy + 1) % h;

    // Sample R channel (displacement is grayscale)
    float c00 = data[(iy  * w + ix)  * 4] / 255.f;
    float c10 = data[(iy  * w + ix1) * 4] / 255.f;
    float c01 = data[(iy1 * w + ix)  * 4] / 255.f;
    float c11 = data[(iy1 * w + ix1) * 4] / 255.f;
    return (c00*(1-dx)*(1-dy) + c10*dx*(1-dy) + c01*(1-dx)*dy + c11*dx*dy);
}

// Triplanar texture sampling (CPU equivalent of GLSL triplanar — used for both disp and emit)
float sampleTexCPU(const TextureSlot& slot, float x, float y, float z, float scale) {
    float ax = std::abs(x), ay = std::abs(y), az = std::abs(z);
    float sum = ax + ay + az + 0.001f;
    float wx = ax/sum, wy = ay/sum, wz = az/sum;

    float dx = sampleBilinear(slot.pixelData.data(), slot.width, slot.height,
                               y*scale*0.5f+0.5f, z*scale*0.5f+0.5f);
    float dy = sampleBilinear(slot.pixelData.data(), slot.width, slot.height,
                               x*scale*0.5f+0.5f, z*scale*0.5f+0.5f);
    float dz = sampleBilinear(slot.pixelData.data(), slot.width, slot.height,
                               x*scale*0.5f+0.5f, y*scale*0.5f+0.5f);
    return wx*dx + wy*dy + wz*dz;
}

// Usage in waveform generation:
// float dispVal = sampleTexCPU(dispTex, pt.x, scanHeight, pt.z, texScale);
// float emitVal = sampleTexCPU(emitTex, pt.x, scanHeight, pt.z, texScale);

```

## 15. Procedural Texture Library

8 built-in procedural textures. Each generates **all 6 channels** (color, normal, roughness, displacement, AO, emissive) from deterministic noise functions, so no external image files are needed.

### 15.1 Noise Foundation

```cpp
// FBM (Fractional Brownian Motion) noise — CPU generation
float fbm(float x, float y, int octaves = 4) {
    float val = 0.f, amp = 0.5f, freq = 1.f;
    for (int i = 0; i < octaves; ++i) {
        val += amp * noise2D(x * freq, y * freq);  // Perlin or simplex noise
        freq *= 2.f;
        amp *= 0.5f;
    }
    return val;
}
```

### 15.3 Generation Pipeline

Each procedural preset is a function that fills 6 RGBA images (one per channel) at a fixed resolution (e.g., 256x256):

```cpp
struct ProceduralTexture {
    juce::Image colorMap, normalMap, roughMap, dispMap, aoMap, emitMap;
};

ProceduralTexture generateCheckerboard(int size = 256);
ProceduralTexture generateBrick(int size = 256);
ProceduralTexture generateMetal(int size = 256);

ProceduralTexture generateCircuit(int size = 256);  // has active emissive!
// ... etc for all 8
```

Normal maps are derived from the displacement map via central-difference gradient:

```cpp
// Generate normal map from displacement
for each pixel (x, y):
    float dL = dispMap.getPixelAt(x-1, y).getRed() / 255.f;
    float dR = dispMap.getPixelAt(x+1, y).getRed() / 255.f;
    float dU = dispMap.getPixelAt(x, y-1).getRed() / 255.f;
    float dD = dispMap.getPixelAt(x, y+1).getRed() / 255.f;
    vec3 normal = normalize(vec3(dL - dR, dU - dD, 1.0));
    // Encode to RGB: normal * 0.5 + 0.5
```

### 15.4 Application

When user selects a library preset:
1. Generate all 6 maps on a background thread
2. Upload all 6 to GL textures
3. Retain displacement AND emissive pixel data for CPU audio sampling
4. Set all `uHasTexXxx` flags to 1.0
5. Trigger wavetable rebuild (displacement + emissive affect audio)
6. Set `activeLibTex` state to highlight the button

When user clicks "Clear":
1. Delete all 6 GL textures
2. Set all `uHasTexXxx` flags to 0.0
3. Clear displacement and emissive pixel data
4. Trigger wavetable rebuild
5. Reset `activeLibTex` state

## 16. HDR Skybox System

The skybox replaces the flat dark background with an HDR environment map. It serves three purposes: **background visuals**, **PBR environment reflections**, and **image-based ambient lighting**. Ships with procedural skyboxes (fully offline) and supports custom `.hdr` file loading.

### 16.1 Skybox Presets (Procedural — Offline)

Generated at runtime using noise and gradient functions. No external files needed.

| Preset | Description | Mood | Reflection Character |
|--------|-------------|------|---------------------|
| **Void** (default) | Near-black `vec3(0.015, 0.025, 0.03)` | Minimal, dark | No reflections (default state) |
| **Dark Space** | Black with sparse subtle stars + faint blue nebula wash | Cosmic, deep | Faint pinpoint specular highlights |
| **Sunset** | Warm orange-to-purple vertical gradient + soft clouds | Warm, cinematic | Gold/amber reflections on surfaces |
| **Studio** | Neutral gray gradient (bright top → dark bottom) + soft fill | Clean, technical | Even, balanced reflections for PBR testing |
| **Nebula** | Rich purple-teal-magenta space clouds (fbm noise) | Colorful, psychedelic | Multicolor reflections shift with rotation |
| **Blue Hour** | Deep blue gradient with pale horizon glow | Cool, ambient | Blue-tinted reflections |

### 16.2 Procedural Skybox Generation

Each preset generates a 512×256 equirectangular HDR image on CPU:

```cpp
// SkyboxSystem.h
struct SkyboxPreset {
    juce::String name;
    // Generator fills an HDR float buffer (RGB, 3 floats per pixel)
    std::function<void(float* rgb, int w, int h)> generate;
};

// Example: Sunset gradient
void generateSunset(float* rgb, int w, int h) {
    for (int y = 0; y < h; ++y) {
        for (int x = 0; x < w; ++x) {
            float v = (float)y / h;          // 0=top, 1=bottom
            float u = (float)x / w;
            // Vertical gradient: deep blue top → orange horizon → dark ground
            float r = mix(0.02f, 1.8f, smoothstep(0.3f, 0.55f, v)) * (v < 0.6f ? 1.f : 0.1f);
            float g = mix(0.01f, 0.6f, smoothstep(0.35f, 0.55f, v)) * (v < 0.6f ? 1.f : 0.05f);
            float b = mix(0.15f, 0.2f, smoothstep(0.2f, 0.5f, v)) * (v < 0.6f ? 1.f : 0.05f);
            // Soft cloud layer
            float cloud = fbm(u * 6.f + 1.f, v * 3.f, 5) * 0.3f;
            r += cloud * 0.4f; g += cloud * 0.15f;
            int idx = (y * w + x) * 3;
            rgb[idx] = r; rgb[idx+1] = g; rgb[idx+2] = b;
        }
    }
}
```

### 16.3 Custom HDR File Loading

Support Radiance `.hdr` (RGBE) format — the most common HDR format, simple to parse (~100 lines of C++):

```
HDR file structure:
  Header: text lines ending with empty line
    - "#?RADIANCE" magic
    - "FORMAT=32-bit_rle_rgbe" format indicator
    - "-Y height +X width" resolution line
  Body: RGBE scanlines (run-length encoded)
    - Each pixel: 4 bytes (R, G, B, E) where RGB * 2^(E-128)

Parse steps:
  1. Read header → extract width, height
  2. For each scanline: decode RLE → 4-byte RGBE pixels
  3. Convert RGBE → float RGB: r = R * 2^(E-128), etc.
  4. Upload to GL as GL_RGB32F or GL_RGB16F texture
```

Implementation via `SkyboxSystem::loadHDR(juce::File)`. The parsed float data is uploaded as an equirectangular GL texture with `GL_CLAMP_TO_EDGE` vertically and `GL_REPEAT` horizontally (for rotation wrap).

### 16.4 Tone Mapping

HDR values can exceed 1.0. Use **Reinhard tone mapping** in the shader (simple and effective):

```glsl
vec3 toneMap(vec3 hdr, float exposure) {
    vec3 mapped = hdr * exposure;
    return mapped / (mapped + vec3(1.0));  // Reinhard
}
```

The `skyboxExposure` parameter (0–5) controls brightness. At exposure=1 the skybox appears at natural brightness. Higher values reveal detail in dark environments; lower values darken bright environments.

### 16.5 Integration with Existing Rendering

The skybox integrates with the existing PBR pipeline:
- **Background**: skybox replaces flat color for miss rays
- **Reflections**: surfaces reflect the skybox, modulated by roughness and `skyboxReflect`
- **Ambient**: skybox tints the ambient lighting term (sampled in normal direction)
- **AO interaction**: AO still darkens crevices — it multiplies the ambient, including skybox-tinted ambient
- **Emissive**: emissive glow is additive on top and not affected by the skybox
- **MRI slice interior**: the cross-section interior rendering is NOT affected by the skybox (keeps its diagnostic teal color)

## 20. Technical Decisions & Gotchas

### Critical: Camera FOV Matching

The GLSL raymarcher uses focal length `1.5`, which means:
- `ray_direction = normalize(uv.x * right + uv.y * up + 1.5 * forward)`
- Vertical half-FOV = `atan(0.5 / 1.5)` = 18.43°
- Full vertical FOV = **36.87°**

Any overlay geometry (scan path, slice plane, custom mesh) MUST use a camera with **exactly 36.87° vertical FOV** or it will drift from the raymarched background, getting worse with zoom.

### Critical: Resolution Uniform

`gl_FragCoord` operates in **framebuffer pixels** (physical pixels). The resolution uniform `uRes` MUST be set to `viewport_width * pixel_ratio, viewport_height * pixel_ratio`, NOT CSS/logical pixels. On Retina/HiDPI displays this is 2× the logical size. If wrong, the raymarcher center will be offset from screen center.

### Wavetable Rebuild Threading

Never rebuild the wavetable on the audio thread. The contour extraction evaluates the SDF ~32,768 times (512 angles × 64 radial steps). This takes 0.5–2ms depending on scene complexity. Use:

1. Message thread timer (33ms / 30Hz) checks dirty flags
2. If dirty: rebuild contour + wavetable on message thread
3. Atomic pointer swap to deliver new wavetable to audio thread
4. Audio thread reads old table until swap, then reads new table

### Voxelization Performance

At 24³ resolution with a 1000-triangle mesh: ~50–200ms. Always run on a background thread with a progress callback for GUI ("VOXELIZING..."). Consider BVH acceleration for meshes >10K triangles.

### Custom Shape Safety

The voxel SDF `sample()` function will be called millions of times. Keep it tight — the trilinear interpolation is the hot path. Ensure bounds checking returns a reasonable default (1.5f) for out-of-bounds queries rather than crashing.

### SDF Evaluation Parity

The CPU scene evaluation (for audio) and the GLSL scene evaluation (for visuals) MUST produce identical results. Maintain them in parallel. Any change to shape scaling, operation math, or domain transforms must be mirrored in both.

### Anti-Aliasing at High Frequencies

The wavetable approach inherently limits bandwidth to `TABLE_SIZE / 2` harmonics per cycle. At 2048 samples this is fine up to ~10kHz fundamental. For higher notes, consider mipmap tables (progressively band-limited versions for higher octaves).

### ADSR Click Prevention

The ADSR must start from the current envelope value on re-trigger (not from zero), and the release must start from the current level (not from sustain). JUCE's `juce::ADSR` handles this correctly if you call `noteOn()` without calling `reset()` first.

### State Save/Load

Use `juce::AudioProcessorValueTreeState::state` for XML serialization. Custom mesh paths should be stored as absolute paths with a fallback "mesh not found" state. Voxel grids should NOT be serialized (too large) — re-import the OBJ on load.

### Texture Memory Management

Each texture channel (color, normal, roughness, displacement, AO, emissive) consumes GPU memory. At 256x256 RGBA:
- ~256 KB per texture × 6 channels = ~1.5 MB total (manageable)
- Procedural generation runs on background thread, then uploads to GL on the OpenGL thread
- Displacement AND emissive pixel data are ALSO retained on CPU (for audio sampling) — ~512 KB additional
- When clearing textures, ensure all 6 GL textures and both CPU pixel data buffers are freed
- Texture upload must happen on the OpenGL thread (queue via `juce::OpenGLContext::executeOnGLThread`)

### Texture-to-Audio Thread Safety

The displacement and emissive pixel data are read by the wavetable generator (message thread) and could be cleared by the user (GUI thread). Use `ThreadSafeSwap` (same pattern as wavetable/voxel data) — atomic pointer swap to deliver new texture data.

### Procedural Texture Generation Cost

Generating 6 maps at 256x256 with fbm noise (4–6 octaves) takes ~10–30ms. Run on a background thread with a loading indicator. The generation is deterministic — same preset always produces the same textures.

### HDR Skybox Considerations

- **Texture format**: Use `GL_RGB16F` for equirectangular skybox textures. `GL_RGB32F` wastes VRAM; `GL_RGB8` loses HDR range. At 512×256 × 6 bytes = ~768 KB per skybox — very manageable.
- **Procedural generation**: Skybox presets are generated at 512×256 resolution. This is sufficient for backgrounds and blurred reflections. Generation cost: ~5–15ms per preset.
- **Custom .hdr loading**: Radiance RGBE format is straightforward to parse. Maximum supported resolution: 4096×2048 (~48 MB in float RGB). Reject larger files with a warning. Parse on background thread.
- **Tone mapping in shader**: The Reinhard operator (`hdr / (hdr + 1)`) is applied per-channel in the fragment shader. This means the skybox texture stores true HDR values and tone mapping happens at render time, controlled by the exposure slider.
- **Reflection blur approximation**: True IBL (Image-Based Lighting) requires prefiltered mip chains for different roughness levels. The cheap alternative used here: the `skyboxBlur` parameter linearly blends the reflection contribution toward zero as roughness increases, giving a "reflection fades on rough surfaces" effect without actually convolving the environment map. This is visually convincing for a synth plugin.
- **macOS OpenGL 4.1 limit**: `GL_RGB16F` textures are supported on GL 3.0+, so macOS is fine. The equirectangular sampling uses basic `texture2D` with no compute shaders required.
- **Skybox does NOT affect audio**: Unlike displacement and emissive textures, the skybox is purely visual. No wavetable rebuild is triggered by skybox parameter changes.

### Plugin Validation

Test with `pluginval` before release. Common issues:
- OpenGL context not properly detached on editor close
- Audio thread allocation (string formatting, vector resize)
- Parameter range mismatches between APVTS and GUI components
- GL texture leaks (ensure all 6 texture slots are freed on editor destruction)

### Integration Notes

- All normal maps use **OpenGL convention** (`_nor_gl` suffix) — Y-axis points up. No need to flip the green channel.
- Some textures are `.jpg` (lossy) vs `.png` (lossless). Both are loadable via `juce::ImageFileFormat`.
- The `.exr` files require OpenEXR parsing. Prefer the `.hdr` files or pre-convert `.exr` → `.hdr` with a tool like `exrtopng` or ImageMagick.
- For factory presets that ship with the plugin: either bundle the textures as binary resources (increases plugin size) or convert the best ones into procedural generators that approximate the look using fbm noise patterns.
